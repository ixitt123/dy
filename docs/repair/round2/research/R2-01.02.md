# R2-01.02 全网研究记录

## 检索信息

- 检索时间：2026-08-05 17:50–17:59（Asia/Shanghai）
- 检索目标：确认未勾选复选框的权威语义、任务关系应使用的稳定标识、SQLite 中可选关系的表达方式，以及怎样兼容既有记录而不把历史 BGM 误绑定到新旁白。
- 关键词：
  - `WHATWG checkbox checkedness unchecked form data`
  - `MDN checkbox unchecked submitted`

## 一手来源与适用性

1. [WHATWG HTML Standard：Checkbox state](https://html.spec.whatwg.org/multipage/input.html#checkbox-state-(type=checkbox))
   - 复选框是明确的二态控件，脚本应读取当前 `checked` 状态；不能用默认属性或历史 UI 偏好代替本次选择。
   - 本项适用：生成请求开始时冻结当前布尔选择，并把 `false` 也显式写入任务元数据。
2. [MDN：`input type=checkbox`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/checkbox)
   - 未勾选复选框在普通表单提交中不会产生 name/value；服务端若要区分“明确未选”和“旧记录没有该字段”，客户端必须显式提交状态。
   - 本项适用：JSON API 请求必须发送 `bgm_requested: false`，不能把缺字段当作可靠的未选择证据。
3. [SQLite：Foreign Key Support](https://www.sqlite.org/foreignkeys.html)
   - 关系应由父/子键精确相等建立；父键通常是主键或唯一键，NULL 表示没有要求存在对应父记录。
   - 本项适用：BGM 只允许通过精确 TTS job ID 关联，禁止按文案、时间或“最近一条”推断。
4. [SQLite：JSON Functions And Operators](https://www.sqlite.org/json1.html#the_json_extract_function)
   - `json_extract` 对不存在路径与 JSON null 均返回 SQL NULL。
   - 本项适用：旧记录缺少 `bgm_requested` 时必须保留“未知/旧版”语义，不能粗暴转换为 `false` 后破坏已有正确四件套。
5. [JSON:API 1.1：Relationships / Resource Linkage](https://jsonapi.org/format/#document-resource-object-relationships)
   - 关系链接由资源标识对象的 `type`/`id` 表达，空关系应显式为 null 或空集合。
   - 本项适用：API 和 DOM 均使用稳定 job ID；文案和显示标题只作为属性，不参与关系判定。

## 本地调用链与根因

- `ui/modules/legacy-runtime.js` 在生成开始时读取 `#ttsGenerateCleanEducationBgm.checked`，但 `/api/tts/generate` 请求没有保存这一选择。
- SQLite 的 `tts_jobs.metadata_json` 因而无法区分：
  - 新任务明确未选择 BGM；
  - 旧任务尚未引入该字段。
- `indexTtsBgmJobs()` 当前只检查 BGM 子记录中的 `parent_tts_job_id/source_tts_job_id`，没有用父任务的显式选择状态拒绝陈旧认领。
- `test-tts-bgm-option.mjs` 硬编码任务 `#93`，依赖 A 机本地 SQLite，B 机全新数据无法复现业务判据；它也没有同时验证 SQLite、API 与 DOM。

## 采用方案

1. `/api/tts/generate` 显式携带并持久化 `bgm_requested: true/false`。
2. API 对外规范化 `bgm_requested`、父任务 ID 和关系确认标志，同时保留旧记录的 `null` 三态兼容。
3. 自动生成或用户补生成的 BGM 写入 `bgm_relation_confirmed: true`；父任务明确为 `false` 时，只接受这类明确确认的补生成关系。
4. 前端建立索引时要求父任务真实存在、不是音乐任务、关系使用精确 ID；不按文本、标题、时间或最近历史匹配。
5. 重写目标测试：通过正常本机 API 导入安全 WAV，构造历史同文案 BGM、陈旧错误认领和新未勾选旁白，验证 SQLite/API/DOM 一致，并在结束时清理测试任务。

## 未采用方案及原因

- 不删除、重写或复制用户现有 SQLite：会破坏历史任务，且不能修复后续新任务。
- 不按文案、标题、创建时间或最近一条任务匹配：这些字段不唯一，正是串绑风险来源。
- 不把所有缺少 `bgm_requested` 的旧记录直接视为 `false`：会让既有合法四件套丢失 BGM。
- 本项不新增独立关系表或大规模 schema 迁移：第二轮 `R2-05.05` 已负责 BGM 单一状态所有者；当前先做向后兼容的最小修复。
- 不使用真实 TTS/BGM Provider 或密钥作为回归前提：供应商外部任务属于 `R2-01.10/R2-01.11`，本项使用可解码安全媒体 fixture。
