# R2-01.14 启动实例身份校验研究

## 目标与冻结证据

- 项目：拒绝错误项目或陈旧 `ui-server.url`。
- 开工包：`.data/repair-evidence/R2-01.14/20260811-084142/current-work-packet.md`。
- 基线：`.data/repair-evidence/R2-01.14/20260811-084142/baseline.json`。
- 修复前失败判据：`test-launcher-project-identity.mjs` 必须证明任意本地 HTTP 200 会被现有启动器误认成当前项目服务。

## 真实调用链与状态所有者

1. `start-ui-hidden.vbs` 只负责预检并调用 `launch-ui.mjs`，不是 URL 身份的判断者。
2. `launch-ui.mjs:existingServerUrl()` 读取当前项目根目录的 `ui-server.url`，对该 URL 执行一次 `fetch(url)`；只要 `response.ok` 就记录 `reuse-existing` 并打开页面。
3. 现有判断没有核对 URL 是否为 loopback origin，也没有核对项目根、服务源文件、commit、实例 ID、PID 或健康状态。
4. `ui-server.mjs` 已维护当前项目的 `ui-server.pid`/`ui-server.url`，并有受浏览器会话保护的 `/api/status`，但没有提供给本地启动器使用的、可绑定到当前服务进程的最小身份响应。
5. 因此真实根因不是等待时间不足，而是“活性”被错误地当成“身份”：任何返回 2xx 的本地或被篡改 URL 都会进入复用分支。
6. 真实服务复验又暴露一层同链根因：`server/core/runtime-process.js` 和启动器通过 Windows PowerShell 5.1 读取 `Win32_Process.CommandLine`，但没有固定标准输出为 UTF-8。项目路径含“短视频”时，Node 收到替换字符 `����Ƶ`，把正确进程误判为其他进程；这同时解释了既有 PID 锁为什么会漏掉活实例并留下 8787/8788 重复服务。

采用的一手资料：

- Node.js Fetch/Undici：`fetch()` 在收到 HTTP 错误状态时也会正常完成，调用方必须检查响应内容，而不应把一次 HTTP 响应当作服务身份。<https://undici.nodejs.org/api/Fetch>
- Node.js Child process：PID 可能被系统重新分配给另一个进程，单独依赖 PID 会产生意外结果。<https://nodejs.org/api/child_process.html>
- Node.js File system：`fs.realpathSync.native()` 可取得规范化真实路径，适合生成当前项目根的稳定摘要。<https://nodejs.org/api/fs.html#fsrealpathsyncnativepath-options>
- Node.js Process：`process.pid` 是当前服务进程的真实 PID，可由服务端在身份响应中提供。<https://nodejs.org/api/process.html#processpid>
- Microsoft PowerShell 字符编码：Windows PowerShell 的默认输出编码并不一致，`$OutputEncoding`/控制台输出编码决定与外部程序通信时的字符编码；包含非 ASCII 路径时必须显式约定。<https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_character_encoding>

适用性：本项目运行于 Node.js 24 / Windows，本项所需的 `fetch`、`AbortSignal.timeout`、`process.pid`、SHA-256 与 `fs.realpathSync.native` 均为当前运行时原生能力，不增加部署依赖。

## 采用方案

1. 服务端增加 loopback Host 约束下的只读身份路由 `/.well-known/douyin-runtime`；不绕过现有 Host 校验，不返回 Cookie、Token、设置或密钥。
2. 身份响应只返回校验所需字段：协议版本、项目根 SHA-256、服务入口 SHA-256、Git commit、随机实例 ID、PID、启动时间和 `ready/starting` 健康状态。项目真实路径只在本机计算和比较，不通过 HTTP 明文暴露。
3. 启动器只接受无用户名密码、无查询/片段、主机为 `127.0.0.1`/`localhost`/`::1` 的 HTTP origin，避免把被篡改的 URL 文件变成任意网络探测器。
4. 启动器对当前项目根、当前 `ui-server.mjs` 内容和当前 commit 独立计算期望值；身份响应必须逐项一致。
5. PID 必须为正整数且对应仍在运行、命令行实际包含当前项目 `ui-server.mjs` 的进程；Windows 命令行查询失败时拒绝复用，不以“查询不到就算通过”兜底。
6. PowerShell 查询进程命令行前显式把 `[Console]::OutputEncoding` 设为无 BOM UTF-8，修复中文项目路径在 Node `encoding: "utf8"` 下被替换的问题；服务器锁和启动器共用同一编码约定。
7. 实例 ID 必须非空，健康状态必须为 `ready`。探测使用有界超时并拒绝重定向。
8. 任一校验失败，只清理错误 `ui-server.url`；随后按原启动链启动当前项目服务。新服务 URL 也必须通过相同身份与健康校验后才记录/打开。

## 未采用方案

- 延长等待、增加重试次数：只能降低偶发启动等待，不能区分错误项目。
- 继续请求首页并匹配标题/HTML：页面内容不是进程身份，且不同副本可能完全相同。
- 只检查端口或 HTTP 200：只能证明端口上有响应。
- 只检查 `ui-server.pid` 或 `process.kill(pid, 0)`：PID 可陈旧或被复用，且不能证明端口属于该 PID。
- 只比较 commit：两个不同目录可能处于同一 commit，仍会错误复用另一个项目副本。
- 公开返回项目绝对路径：没有必要，会额外暴露本机目录信息；改为本地计算 SHA-256 后比较。
- 使用默认值或把缺失字段视为通过：会继续掩盖身份缺失，必须失败关闭。

## 验收设计

- 修复前：真实本地 HTTP 200 假服务写入 `ui-server.url` 后，启动器错误记录 `reuse-existing`，回归测试失败。
- 修复后：分别拒绝无身份响应、错误项目摘要、错误入口摘要、错误 commit、错误 PID、空实例 ID、非 ready 健康状态和非 loopback URL。
- 正确服务：身份、PID、commit、项目根、入口哈希、实例 ID 与健康状态全部一致时才复用。
- 错误 URL：被清理，当前项目的最小真实服务被启动，新的 URL 再次通过同一身份探测。
- 执行目标回归、R2-01.12/R2-01.13 兼容回归、完整 `check:gate`、第二轮检查及 `git diff --check`。
