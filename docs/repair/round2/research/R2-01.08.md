# R2-01.08 修改前全网研究：MoneyPrinter 包装任务 ID 与最终资产 ID

- 关键词：`MoneyPrinterTurbo task_id API official repository`、`MoneyPrinterTurbo /api/v1/videos task_id`、`SQLite primary key unique constraint official`、`WHATWG URLSearchParams id`、`Node createHash SHA-256 file identity`。

## 一手来源与适用性

### 1. MoneyPrinterTurbo 上游异步任务模型

- 来源：[MoneyPrinterTurbo API Overview](https://www.mintlify.com/harry0703/MoneyPrinterTurbo/api/overview)、[上游 `app/controllers/v1/video.py`](https://github.com/harry0703/MoneyPrinterTurbo/blob/main/app/controllers/v1/video.py)、[上游 `app/controllers/base.py`](https://github.com/harry0703/MoneyPrinterTurbo/blob/main/app/controllers/base.py)。
- 要点：上游 `POST /api/v1/videos` 立即返回 `task_id`，随后使用同一个上游 ID 查询 `/api/v1/tasks/{task_id}`；上游控制器生成/传递的是异步任务身份，不是本项目最终资产注册表身份。
- 适用性：主程序为容错切换素材源而创建 `dy-mpt-<uuid>` 包装任务，并另存 `official_task_id` 是合理边界；两者必须保持独立且可恢复，不能把最终资产 ID 回写覆盖任一任务 ID。

### 2. MoneyPrinterTurbo 上游源码的任务目录归属

- 来源：[MoneyPrinterTurbo 官方仓库](https://github.com/harry0703/MoneyPrinterTurbo)、当前冻结子模块 `d994b15fc8f4b8a9eeb7d43cc8aed4a2a0e2c3f2` 中的 `app/controllers/v1/video.py`、`app/services/task.py` 与 `app/utils/utils.py`。
- 要点：上游任务 ID 同时用于队列、状态查询与 `storage/tasks/<task_id>` 产物目录，属于上游运行身份。
- 适用性：本项只能修主程序集成；不应修改子模块内部，也不能用主程序内容寻址的资产 ID 替换上游任务目录 ID。

### 3. SQLite 主键与唯一约束

- 来源：[SQLite CREATE TABLE](https://www.sqlite.org/lang_createtable.html)、[SQLite Transaction](https://www.sqlite.org/lang_transaction.html)。
- 要点：`PRIMARY KEY`/`UNIQUE` 用于约束各自数据模型的身份和去重边界；事务保证写入的原子可见性。
- 适用性：`money_printer_jobs.id`、`money_printer_assets.id` 和 `final_assets.asset_id` 是三个不同表的主键。最终资产注册表还以 `(source, source_ref, kind, sha256)` 唯一约束去重；应通过显式字段建立引用，不应依赖碰巧相同的字符串。

### 4. URL 参数必须携带真实最终资产 ID

- 来源：[WHATWG URL Standard](https://url.spec.whatwg.org/#urlsearchparams)。
- 要点：查询参数是 URL 的结构化组成，`URLSearchParams.get("id")` 可读取文件端点使用的资源键。
- 适用性：页面预览和下载使用 `/api/final-assets/file?id=<assetId>`，因此 DOM 的 `data-final-asset-id` 必须等于该 URL 的 `id` 以及 API `assetId`，不得等于包装/渲染任务 ID。

### 5. 内容哈希验证

- 来源：[Node.js `node:crypto`](https://nodejs.org/api/crypto.html#class-hash)。
- 要点：`Hash.update()`/`digest()` 可对同一字节序列生成可复验摘要。
- 适用性：最终资产注册表以 SHA-256 参与稳定 ID 与唯一约束；真实浏览器测试还应分别读取预览、下载和物理下载文件，证明三者 SHA-256 一致，而不能只比较 URL 字符串。

### 6. HTTP Range 与冷缓存媒体恢复

- 来源：[RFC 9110 HTTP Semantics](https://httpwg.org/specs/rfc9110.html)、[MDN HTTP range requests](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Range_requests)、[Node.js `fs.createReadStream`](https://nodejs.org/api/fs.html#fscreatereadstreampath-options)。
- 要点：`bytes=-N` 表示资源末尾 N 字节，不是 `0-N`；合法单范围返回准确 `206/Content-Range/Content-Length`，越界或畸形范围返回 `416`；Node 文件流 `start/end` 为包含端点。
- 适用性：重启后的 fresh Chrome 没有前一进程缓存，会重新对统一最终资产端点发起随机/后缀请求。当前 `sendFinalAssetFile()` 把 `bytes=-16` 错解为 `bytes 0-16`，导致真实视频在 metadata 已就绪后仍无法从 0 秒推进；必须修复统一端点而不是放宽播放断言。

## 本地调用链与修改前证据

- `/api/money-printer/generate` 创建主程序包装任务 `dy-mpt-<uuid>`，`money_printer_jobs.id` 保存包装 ID，`official_task_id` 保存上游 `task_id`；页面轮询包装 ID，服务端再映射到上游 ID。
- `/api/money-printer/render-final` 的 `renderFinalVideo()` 另建 `money-printer-<timestamp>` 渲染运行 ID；最终成片进入 `finalAssetRegistry.register()` 后取得内容/归属派生的 `asset_<sha>_<owner>`。
- 服务端响应同时含旧兼容字段 `id`（渲染包装 ID）与 `assetId`（最终资产注册表 ID），预览/下载 URL 使用后者；页面当前从 URL 反解析 `id` 写入 DOM。
- 旧 `test-money-printer-final-asset-browser.mjs` 先硬编码读取本机 TTS 任务 `93`。B 主机没有该记录，修改前于浏览器 JS 调用链失败，未进入资产身份断言。
- 修改前日志：`.data/repair-evidence/R2-01.08/20260805-203127/pre-fix/01-final-asset-browser.log`；SHA-256 `49F5E4B0C25F16B16988BFDFDDB998436E9CF9AE11613D4123399FC3DDA22D3F`。
- 旧测试后续断言 `DOM assetId === finalAsset.id` 与验收语义相反：它把最终资产 ID 强制等同渲染包装 ID，可能把正确实现报错，也无法验证 API 的显式 `assetId`、注册表和响应头是否一致。
- 增强后的重启诊断还冻结了第二层根因：首次进程内预览可播放，但重启后的 fresh Chrome 在 `readyState >= 1` 后仍停在 0 秒；统一最终资产端点的后缀 Range 实际返回开头 17 字节，与标准要求的末尾 16 字节不符。
- Range 失败日志：`.data/repair-evidence/R2-01.08/20260805-203127/diagnostic-4-range-before-fix.log`；SHA-256 `BA9AB7699522E3340836CB38EE1A24E6662034AF08DC02480B50186D5F7578F3`；准确差异为实际 `bytes 0-16/47101`、期望 `bytes 47085-47100/47101`。

## 采用方案

1. 保留三种身份的独立性：主程序包装任务 ID、上游官方任务 ID、最终资产 ID；不改上游子模块。
2. 最终渲染响应保留 `id` 兼容字段，同时新增明确的 `wrapperId`，并继续以 `assetId` 作为最终资产注册表、预览 URL、下载 URL和 DOM 数据属性的唯一身份。
3. 页面 `showFinalAsset()` 显式接收 `assetId`，验证它与预览 URL 的 `id` 一致；状态中分别保存 `finalWrapperId` 和 `finalAssetId`，不再只靠 URL 反解析隐式传递。
4. 把两项浏览器回归改为自包含安全 fixture 和唯一 TTS handoff，不依赖本机任务 `93`；失败也输出 JSON/截图并按精确 ID 清理。
5. 真实浏览器验证包装 ID 与资产 ID 不相等、API/DOM/URL/`X-Final-Asset-Id`/注册表一致，预览、下载请求和物理点击下载 SHA-256 一致；服务重启后再次验证相同资产 ID、哈希与包装任务映射。
6. 修复统一最终资产文件端点的单字节 Range 语义，并覆盖首段、后缀、开放尾段、畸形、多范围、零后缀和越界请求，使冷缓存播放与重启恢复使用同一正确资源。
7. 保持旧 `id` 字段和旧文件端点兼容；只增加显式字段与一致性检查，避免破坏既有调用方。

## 未采用方案及原因

- 把最终资产 ID 覆盖到 `task_id` 或 `official_task_id`：会破坏上游轮询、失败回退和重启恢复映射。
- 让注册表资产 ID 直接等于渲染运行 ID：失去内容哈希与归属去重语义，同一运行产物变更后无法可靠识别。
- 只把旧测试的 `id` 改成 `assetId`：仍依赖另一台机器的 TTS `93`，也没有证明包装 ID 独立、注册表响应头一致和重启恢复。
- 用 mock API、静态 DOM 或绕过浏览器物理下载：不能证明实际服务、SQLite、最终文件端点和浏览器下载链。
- 修改 MoneyPrinterTurbo 子模块：违反本项边界且无法解决主程序自己的 ID 映射问题。

## 研究结论

正确模型不是“所有 ID 统一为同一个值”，而是“每个状态所有者保留独立 ID，并通过显式字段与持久化引用一致映射”。当前主程序服务端已具备大部分分离基础，但响应字段仍有 `id` 歧义，页面未显式保存两种最终身份，旧回归还反向要求相等且依赖机器私有数据。本项应做最小兼容增强，并用自包含真实浏览器、哈希和重启证据锁定身份边界。

## 实施后诊断结论

- 修复后的最终资产浏览器诊断通过：API、DOM、URL、注册表和 `X-Final-Asset-Id` 使用同一资产 ID，渲染包装 ID 保持独立；预览、下载响应和浏览器物理下载文件 SHA-256 一致。
- Range 诊断通过首段、后缀、开放尾段、畸形、多范围、零后缀和越界矩阵，`bytes=-16` 正确返回末尾 16 字节。
- 第 1 次正式复验在重启用例的一次性 8080 PID 取样失败；随后增强失败清理与端口稳定等待。进一步诊断发现 fresh Chrome 的文件已完整缓冲且无媒体错误，但相同状态的重复 `renderTask()` 会替换正在播放的 `<video>` 节点，使已成功的 `play()` 立即回到新节点的暂停状态。
- 页面现在只在最终资产列表标记发生变化时重建播放器；真实重启诊断通过：8787 服务 PID 发生变化后，8080 PID 保持不变，包装任务映射、最终资产 ID、哈希和旧包装文件端点均可恢复，fresh Chrome 播放推进到 `0.168183s`。诊断报告 `.data/repair-evidence/R2-01.08/20260805-203127/diagnostic-12-preserve-player/tests/money-printer-restart-recovery.json`，SHA-256 `B4D81F963BD847CDAE31FF06BC331F23F528B6CA43343B0D8A1699795CF2F301`。
- 播放器生命周期修正后的最终资产浏览器复验再次通过，报告 SHA-256 `B1402CBA78B4947C2CAF2A4702D6E95058F9258EEEF56E80991AA9B033402C7C`。
- 兼容抽查 `test-money-printer-production.mjs` 通过。旧 `test-money-printer-final-bgm-handoff.mjs` 仍依赖本机固定 TTS 任务，当前主机缺少该私有记录，未将其误记为本项源码失败；正式验收使用本项自包含 handoff。
