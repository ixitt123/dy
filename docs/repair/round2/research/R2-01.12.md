# R2-01.12｜VBS 缺依赖时可见失败并停止：研究记录

- 检索日期：2026-08-05
- 中文关键词：Windows Script Host Run 等待返回码、wscript 可见错误提示、Node.js spawn 缺少入口错误、隐藏启动器依赖预检
- English queries: `WScript.Shell Run wait return exit code`, `WScript.Shell Popup error message`, `Node.js child_process spawn ENOENT error event`, `Node.js process exitCode graceful exit`

## 一手资料

1. [Microsoft WSH Run Method](https://learn.microsoft.com/en-us/previous-versions/windows/internet-explorer/ie-developer/windows-scripting/d5fk67ky(v=vs.84))：`bWaitOnReturn=True` 时脚本等待被启动程序结束并取得其退出码；不等待时方法立即返回，返回值固定为 0，无法反映子进程失败。
2. [Microsoft WSH Popup Method](https://learn.microsoft.com/en-us/previous-versions/windows/internet-explorer/ie-developer/windows-scripting/x83z1d9f(v=vs.84))：`WshShell.Popup` 可由图形脚本宿主显示带错误图标和超时的可见提示。
3. [Microsoft wscript command](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/wscript)：`wscript.exe` 是 Windows Script Host 的图形宿主；自动化复验可用控制台宿主 `cscript.exe` 获取输出。
4. [Node.js child_process](https://nodejs.org/api/child_process.html)：`spawn()` 启动失败会触发 `error`；后台长驻进程应同时使用 `detached`、独立的标准输入输出以及 `unref()`；默认不经 shell。
5. [Node.js process](https://nodejs.org/api/process.html)：可设置 `process.exitCode` 并让进程自然结束，以便错误信息完成写出。

## 当前调用链与根因

`start-ui-hidden.vbs` 查找 Node 后检查依赖包，再以隐藏、非等待模式运行 `launch-ui.mjs`。当前存在三个确定问题：

1. 缺少依赖包时只写日志，仍继续启动，形成“已报错但继续运行”的半残服务路径。
2. `shell.Run(..., False)` 不等待子程序；根据微软文档，该模式无法取得真实退出码，因此 `launch-ui.mjs` 的失败会被 VBS 当作成功。
3. `launch-ui.mjs` 未预检 `ui-server.mjs` 和依赖包，也未观察后台 `spawn` 的启动错误，入口缺失时主启动器仍可正常退出。

缺少 Node 时虽然已有非零退出，但在 `wscript.exe` 隐藏启动场景中仅写文件日志，用户看不到可操作提示。

## 采用方案

- VBS 在启动前分别检查 Node、依赖包和 `launch-ui.mjs`；任一缺失时写入 `.data/launcher.log`、向当前宿主显示可操作错误，并以非零状态停止。
- `wscript.exe` 使用带超时的错误弹窗；`cscript.exe` 写入标准错误，便于真实自动化复验且不会留下无人值守弹窗。
- 支持可选的 `DOUYIN_LAUNCHER_NODE` 环境变量作为明确的 Node 路径；设置后不再静默回退，既方便隔离运行时，也可真实复验“Node 路径不存在”。
- VBS 等待短生命周期的 `launch-ui.mjs` 结束，记录并传递非零退出码。真正的 UI 服务仍由 Node 启动器以 detached 模式后台运行，所以正常启动不会长期阻塞 VBS。
- Node 启动器在复用现有服务或创建后台服务之前预检依赖包和 `ui-server.mjs`；缺失时输出可操作错误并设置非零退出码。
- 保留现有服务复用、隐藏窗口、无 shell 启动和后台服务生命周期行为。

## 未采用方案

- 只增加日志：隐藏启动下用户仍看不到，不能满足“可见失败”。
- 增加固定延迟或重试：无法修复确定缺失的文件或依赖，反而延长失败时间。
- 让 VBS 同步等待整个 UI 服务：会使启动脚本永久占用，破坏后台启动设计。
- 只依赖 Node 的异步 `error` 事件：主进程当前立即退出，错误事件存在丢失窗口；入口预检更直接、可复验。
- 自动运行 `pnpm install`：会擅自联网并修改依赖状态，不适合作为启动器的错误恢复。

## 验收口径

- 缺 Node、依赖包或启动入口时：用户获得可操作错误、日志存在、退出码非零、不得产生半残服务标记。
- Node 入口直接缺少 `ui-server.mjs` 时同样非零失败。
- 依赖与入口齐全时，正常隐藏启动仍成功。
- 真实 Windows `cscript.exe` 隔离夹具覆盖失败和成功路径；随后执行仓库完整门禁。
