# R2-01.15 单实例并发与竞态研究

## 冻结状态与已观察失败

- 开工包：`.data/repair-evidence/R2-01.15/20260811-092311/current-work-packet.md`。
- 基线：`.data/repair-evidence/R2-01.15/20260811-092311/baseline.json`。
- R2-01.14 真实重启期间曾同时观察到同一项目的 `ui-server.mjs` 分别监听 8787 与 8788；两者 commit 相同且任务运行数均为 0。中文路径 PID 乱码是其中一个已修根因，但启动器层仍没有把“探测、清理、启动、身份确认”组成单一互斥事务。

## 调用链与竞态根因

1. 多个 `launch-ui.mjs` 可以同时读取空的或尚未发布的 `ui-server.url`。
2. 每个启动器都会独立进入 `existingServerUrl()`；没有候选 URL 时会执行状态清理，再各自启动一个 `ui-server.mjs`。
3. 服务端 `fs.openSync(pidPath, "wx")` 能原子决定一个 PID 文件胜者，但无法阻止较晚的启动器在胜者“已取得 PID、尚未发布 ready 身份”期间把它当成无效状态并停止/清理。
4. 因此服务端锁只保护“多个服务进程同时抢 PID”，没有保护启动器的完整状态转换；真实状态所有者跨在两个进程层，事务边界缺失才是剩余根因。

## 外部检索

检索时间：2026-08-11 09:24（Asia/Shanghai），AnySearch 匿名模式。

- `fs open wx exclusive create EEXIST concurrent lock file server listen EADDRINUSE`，`code.doc`，library=`node`
- `site:nodejs.org/api fs open wx exclusive flag EEXIST server listen EADDRINUSE`

一手资料：

- Node.js `fs` 的 `wx` 映射到 `O_CREAT | O_EXCL`，Windows 使用 `CREATE_NEW`，文件已存在时原子失败；适合选出唯一锁拥有者。<https://github.com/nodejs/node/blob/main/lib/internal/fs/utils.js>
- Node.js `net` 文档把 `EADDRINUSE` 定义为端口已被其他服务占用后的监听失败；它是最后防线，不应代替项目级启动事务。<https://nodejs.org/api/net.html>
- Node.js `fs.mkdir()` 在 `recursive: false` 时，如果目录已存在会返回 `EEXIST`；固定路径目录可作为跨进程互斥的原子竞争点。<https://nodejs.org/api/fs.html>
- Node.js 官方仓库的并发目录创建案例同样显示：并发调用中只有一个创建者成功，其他调用收到 `EEXIST`。<https://github.com/nodejs/node/pull/53534>

## 采用方案

1. 保留服务端 `pidPath` 的 `wx` 原子锁，继续作为唯一服务所有者的最终权威。
2. 在启动器增加项目级 `.data/launcher-start.lock` 目录锁，把“复用探测、陈旧状态清理、服务启动、身份 ready 确认”放在同一互斥区间。
3. 锁目录内写 owner JSON（启动器 PID、runId、创建时间）；等待者仅在 owner 已死亡或无 owner 且目录确实陈旧时恢复，不能按固定延时删除活锁。
4. 释放锁前核对 runId，避免被恢复后的旧启动器删除新锁。
5. 等待有上限；超时必须非零失败并留下结构化日志，不能绕过锁再启动。
6. 并发验收使用真实多进程、中文路径和延迟启动窗口，检查所有启动器结果、最终 PID/URL/身份、监听端口、日志完整性和孤儿进程。
7. 真实重启进一步证明 `scripts/service-restart.mjs` 会以相对入口启动 `ui-server.mjs`；启动器不能再把“命令行是否包含绝对入口路径”作为健康身份的必要条件。健康复用改以回环 HTTP 身份中的项目根哈希、服务源码哈希、commit、instanceId、PID、health 和本机进程存活共同判定；命令行路径只保留在失效状态清理时，防止误杀无关进程。

## 未采用方案

- 只增加启动延时或重试：会缩小概率，不能消除并发窗口。
- 只依赖端口 `EADDRINUSE` 后递增到 8788：会把单实例缺陷变成多端口重复实例。
- 删除服务端 PID 锁：会失去最终原子所有权。
- 只让每个启动器各自等待 URL：没有互斥时，等待者仍可能清理正在启动的胜者。
- 用日志锁兼任启动锁：日志写入是短临界区，启动事务可能持续十几秒，职责和恢复条件不同。
