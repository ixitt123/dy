## 一手来源、结论与适用性

### 1. GitHub Advisory Database / 上游安全公告

- GitHub Reviewed 公告：https://github.com/advisories/GHSA-4xrf-jv44-h6hh
- 上游公告：https://github.com/beaugunderson/ip-address/security/advisories/GHSA-4xrf-jv44-h6hh
- 标识：GHSA-4xrf-jv44-h6hh / CVE-2026-69198，Moderate，CWE-20 / CWE-918。
- 受影响版本：`>=10.1.1 <=10.2.1`；首个修复版本：`10.2.2`。
- 根因：特殊用途分类器复用 `isInSubnet`；接收者自身前缀短于参考范围时提前返回 `false`。因此 `127.0.0.1/0`、`10.0.0.5/7`、`169.254.169.254/0`、`::1/0`、`fc00::1/0` 等仍指向内部目标，却可能被分类为普通地址。
- 适用性：项目当前通过根 `pnpm.overrides` 锁定 `10.3.1`，已经高于首个修复版本；仍需动态证明实际安装树、公告样例与应用信任边界，避免以后锁文件回退。

### 2. 上游修复提交与发布

- 修复提交：https://github.com/beaugunderson/ip-address/commit/488fe9bc7c35363b4b090494fc38c266d217740d
- 修复发布：https://github.com/beaugunderson/ip-address/releases/tag/v10.2.2
- 上游把“网络是否包含于另一网络”和“主机位是否落在特殊范围”拆开：保留 `isInSubnet` 的网络包含语义，新增不受输入 CIDR 后缀影响的 `isHostInSubnet`，并让 IPv4/IPv6 特殊用途分类器使用后者。
- 上游测试覆盖所有前缀长度、IPv4/IPv6 特殊范围、公共地址不误判以及网络包含语义不回归。
- 适用性：本项目不应复制或魔改上游分类器；应验证当前真实传递依赖确为修复版本，并锁住公告样例。

### 3. 公告对 URL 输入的可达性说明

- 同一上游公告明确说明：CIDR 后缀不能作为 URL host；`new URL('http://127.0.0.1/0')` 的 hostname 是 `127.0.0.1`，pathname 是 `/0`。
- 利用前提是应用接收可能带 CIDR 的裸地址字符串，再直接交给分类器；典型表面是 allow/deny 字段、裸 webhook 主机或代理目的地址。
- 适用性：本项目公开入口接收完整 URL，不能把合法路径 `/0` 一律当成 CIDR 攻击。应用回归必须同时证明内部 URL 仍按 hostname 拒绝、公共 URL 的 `/0` 路径仍可通过、伪造的 DNS CIDR 结果不会进入连接层。

### 4. Node.js 24 `node:net` 官方文档

- 来源：https://nodejs.org/download/release/v24.16.0/docs/api/net.html#netisipinput
- `net.isIP('127.0.0.1/24')` 返回 `0`；IPv4 只接受无前导零的点分十进制字面量。
- `BlockList.addSubnet` 把地址与 prefix 作为两个独立参数，IPv4 prefix 限定 `0..32`，IPv6 prefix 限定 `0..128`。
- 适用性：项目 DNS 结果必须是纯 IP，不应携带 CIDR；当前守卫以 `net.isIP` 验证 DNS 返回值，能在请求前拒绝伪造的 `127.0.0.1/0` 或 `::1/0`。

### 5. IETF / RFC 地址语义

- RFC 4632：https://www.rfc-editor.org/rfc/rfc4632.html ，确认 `0.0.0.0/0` 是覆盖全部 IPv4 地址的默认路由，短前缀是合法网络表达，不等于普通单主机地址。
- RFC 1918：https://datatracker.ietf.org/doc/html/rfc1918 ，定义 `10/8`、`172.16/12`、`192.168/16` 私网范围。
- RFC 4193：https://datatracker.ietf.org/doc/html/rfc4193 ，定义 IPv6 `fc00::/7` Unique Local 范围。
- RFC 5156：https://datatracker.ietf.org/doc/html/rfc5156 ，汇总 `::1/128`、`::/128`、`fe80::/10`、`fc00::/7` 等不应作为普通公网目标的特殊 IPv6 范围。
- 适用性：分类必须基于规范化后的主机位，而不能让调用者附加的更短 prefix 改变安全属性。

## 本机诊断结果

1. `pnpm.cmd why ip-address` 显示唯一解析版本为 `10.3.1`，路径为 `@yc-w-cn/douyin-mcp-server -> @modelcontextprotocol/sdk -> express-rate-limit -> ip-address`。
2. 从 pnpm 实际虚拟仓库中沿 `express-rate-limit` 的依赖链接加载 `ip-address@10.3.1`：
   - `127.0.0.1/0.isLoopback() === true`
   - `10.0.0.5/7.isPrivate() === true`
   - `169.254.169.254/0.isLinkLocal() === true`
   - `::1/0.isLoopback() === true`
   - `fc00::1/0.isULA() === true`
3. 项目守卫已拒绝 `http://127.0.0.1/0`、`http://10.0.0.5/7`、`http://[::1]/0`、`http://[fc00::1]/0`。
4. lookup 返回 `127.0.0.1/0` 时，守卫以“DNS 返回无效 IP 地址”在 `requestImpl` 前拒绝。
5. 当前缺陷不是已知绕过仍可复现，而是项目没有独立的 `test-cidr-normalization.mjs`，无法阻止将来依赖或应用层回退。

## 采用方案

1. 保持 `ip-address@10.3.1` 精确 override，不降级、不重复升级；测试读取 `package.json`、锁文件和 pnpm 实际依赖链接，证明运行时分类器是修复版本。
2. 新增 `test-cidr-normalization.mjs`，执行公告中的 IPv4/IPv6 `/0` 与短前缀分类样例，要求所有内部目标仍被识别。
3. 在同一测试中执行应用层动态回归：内部 URL 即使路径形似 `/0` 仍阻断；公共 URL 的 `/0` 路径不误杀；DNS 返回带 CIDR 的非 IP 字符串时不得调用请求层。
4. 把目标测试加入 `check:gate`，使依赖、URL 解析、DNS 验证和 socket 前置拦截以后不能静默回退。
5. 若以上测试在当前代码直接通过，不为制造源码差异而重写 `ssrf-guard.mjs`；本项以补齐安全回归和门禁闭环为最小正确维修。

## 未采用方案及原因

- 不拒绝所有 pathname 为 `/数字` 的 URL：公告明确该部分是 URL 路径，不是 host CIDR； blanket 拒绝会破坏合法公网资源。
- 不把完整 URL 原文直接交给 `Address4` / `Address6`：分类器接收的是裸地址，混用输入语法会制造新的解析分歧。
- 不复制上游 `isHostInSubnet` 到项目源码：当前依赖已修复，复制实现会产生双重状态所有者和后续漂移。
- 不只检查 `package.json` 字符串：必须加载实际 pnpm 传递依赖并执行公告 PoC，防止锁文件或安装树与声明不一致。
- 不把 `R2-02.04` 的 IPv4-mapped/NAT64 全部实现并合并到本项：该项有独立编号、验收和次数预算，本项只保留上游公告中必要的前缀不变性断言。
- 不修改 MoneyPrinterTurbo、全局 Node/pnpm、设置、SQLite、密钥或本地素材：均不属于本项信任边界。
