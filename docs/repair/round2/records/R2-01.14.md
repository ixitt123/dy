# R2-01.14 拒绝错误项目或陈旧 URL｜维修记录

## 结论

根因已定位并修复，不是通过延时或默认值掩盖：

1. 启动器过去把任意 HTTP 2xx 当成当前项目服务，完全没有项目、源文件、commit、实例、PID 与健康绑定。
2. Windows PowerShell 读取 `Win32_Process.CommandLine` 时未固定 UTF-8，中文项目路径“短视频”变成 `����Ƶ`，使正确 PID 被误判为其他进程；这也会让单实例锁漏掉活进程并留下重复端口。

## 修改

- `ui-server.mjs`
  - 增加 `/.well-known/douyin-runtime` 只读身份路由，仍先经过原有 loopback Host 校验。
  - 返回项目根 SHA-256、入口 SHA-256、commit、随机实例 ID、PID、启动时间与健康状态，不暴露项目绝对路径、Cookie、Token、设置或密钥。
  - 写入并清理 `.data/ui-server.identity.json`；URL 只在任务队列就绪、身份状态为 `ready` 后发布。
- `launch-ui.mjs`
  - 只接受合法 loopback HTTP origin，拒绝用户名密码、路径、查询、片段和重定向。
  - 逐项核对项目根摘要、入口摘要、commit、实例 ID、PID、进程命令行与健康状态。
  - 错误 URL 记录 `reject-existing` 后清理；新服务也必须通过同一身份校验后才记录和打开。
  - 保持等待有界；15 秒用于本机真实完整服务启动，不作为身份判断的替代。
- `server/core/runtime-process.js`
  - PowerShell 标准输出显式设为无 BOM UTF-8，使包含中文的真实命令行可与当前入口路径准确比较。
- 测试
  - 新增 `test-launcher-project-identity.mjs`；真实 Windows 中文路径夹具验证错误 HTTP 200 被拒绝、正确服务启动和同一 PID 再复用。
  - `test-launcher-log-rotation.mjs` 的复用夹具升级为真实身份服务，继续验证 R2-01.13 的结构化日志、并发与轮转。
  - `test-page-lifecycle.mjs` 从旧变量名/首页探测静态断言更新为身份绑定与验证后复用断言。
