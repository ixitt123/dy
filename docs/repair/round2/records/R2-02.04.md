## 强制全网研究

修改业务源码前已检索 GitHub Reviewed Advisory、上游修复提交/发行版、IETF RFC 4291/6052/5156 和 Node.js v24 `net`/`http`/DNS 官方文档。完整关键词、来源、适用性、采用与未采用方案见：

- `docs/repair/round2/research/R2-02.04.md`

核心结论：必须按地址位识别 `::ffff:0:0/96` 与 `64:ff9b::/96` 的低 32 位 IPv4；link-local 必须按 `fe80::/10`；解析后仍要在 socket 连接前复验最终 address/family 并固定连接地址。

## 根因与修改

### `server/core/ssrf-guard.mjs`

- 原实现只在 `::ffff:` 后仍包含点号时检查 IPv4；WHATWG URL 会把点分写法规范化成十六进制，造成稳定绕过。
- 原实现没有 NAT64 Well-Known Prefix，且把 link-local 错写成字符串 `fe80`，漏掉 `fe90`–`febf`。
- 用 Node 24 `net.BlockList` 建立原生 IPv6 CIDR及 mapped/NAT64 的内嵌 IPv4 CIDR规则，不手写 IPv6 展开器。
- 统一验证实际 address、声明 family 与 `net.isIP` 结果，拒绝无效/不一致/特殊用途地址并返回冻结副本。
- DNS 结果继续全量校验；选择目标后在请求实现前再次调用 `assertSafeSocketTarget`；真实 HTTP lookup 只返回最终冻结地址，保持 DNS pinning。

### `test-socket-target-revalidation.mjs`

- 覆盖 mapped 点分与十六进制、NAT64 loopback/metadata、完整 link-local `/10`、DNS 请求不得发生、family mismatch、内嵌公网 IPv4允许及最终地址冻结。

### `package.json`

- 把新回归加入 `check:gate`；未改锁文件、依赖版本或安装状态。
