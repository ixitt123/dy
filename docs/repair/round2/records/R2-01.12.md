## 根因

`start-ui-hidden.vbs` 在依赖缺失时只写日志仍继续执行，并以 `shell.Run(..., False)` 启动 Node。微软文档确认不等待模式会立即返回 0，无法传播 `launch-ui.mjs` 的真实失败。Node 启动器本身也未预检依赖和 `ui-server.mjs`，且没有等待后台进程的 `spawn/error` 结果。因此缺依赖或入口时会表现为启动成功，实际留下半残启动路径。

研究和取舍详见 `docs/repair/round2/research/R2-01.12.md`。

## 修改

1. `start-ui-hidden.vbs`
   - 启动前检查 Node、依赖包和 `launch-ui.mjs`。
   - 失败时写日志；`cscript.exe` 输出标准错误，`wscript.exe` 使用带超时错误弹窗；随后返回非零状态。
   - 等待短生命周期 Node 启动器并传播退出码；UI 服务仍由 Node 以后台模式运行。
   - 支持明确的 `DOUYIN_LAUNCHER_NODE` 路径，设置后不静默回退。
2. `launch-ui.mjs`
   - 启动前检查依赖包与 `ui-server.mjs`。
   - 等待子进程的 `spawn/error` 结果；启动失败时输出错误并设置非零退出码。
   - 保留现有服务复用、隐藏窗口、无 shell 与 detached 后台运行。
3. `test-launcher-missing-dependency.mjs`
   - 使用真实 Windows `cscript.exe` 和隔离临时目录验证缺 Node、缺依赖、缺 VBS 入口、缺 Node 服务入口及正常启动五条路径。
   - 可把每条真实退出码、输出、日志和半残服务标记写入证据 JSON。
